# 第十一阶段使用说明

本阶段是第十阶段自动开口的可靠性修复，没有新增模式或改变时机、次数。关闭旧窗口后，通过原`启动小泽本地试聊.cmd`重开即可，无需安装依赖或迁移数据。

ASTRA后续复盘补充：手动发送与手动评估遇到工作线程无法启动、或启动前界面绘制失败时，现在也会释放忙碌状态、保留输入和原记录，并停止已有自动模式。可核对提示后再手动操作，不会自动重试。详情见[ASTRA第十一阶段复盘](ASTRA第十一阶段复盘.md)。第十二阶段任务书已准备，增强尚未实现。

开启步骤仍见[第十阶段使用说明](第十阶段使用说明.md)：只在主人私聊，亲自开启“自动考虑开口”；默认只留草稿，可另外选择“自动加入本地聊天”。两项每次启动关闭。模型模式可能计费，本地采用不会发送微信。

本轮改进：

- 自动线程或定时器启动失败后，自动保持关闭，不再让普通发送一直处于忙碌状态。检查窗口状态后可正常手动聊天；重新开启自动仍从10分钟空闲开始。
- 检查/完成核对遇到界面错误时，停止本次自动会话。已有草稿保留为待处理，不会稍后补采用，也不自动重试。
- 停止和关闭窗口不再依赖自动状态栏能否正常绘制。若状态栏也出现显示问题，可关闭重开，不要反复评估或采用来修复界面。
- 有效话题恰在预检后到期时，会显示实际本地等待原因；没有调用模型，就不会说模型选择沉默或新增10分钟冷却。合法模型silent仍按原规则计请求尝试并冷却。

默认10分钟空闲、30秒检查、北京时间23:00—08:00安静；自动模型请求尝试及自动本地开口各滚动小时2次、本次程序会话6次，切换/重新开启不清零，程序重启重置。手动请求不在自动配额中；已发请求无法撤回，可能仍计费。

真实使用频率和语言效果仍待用户自选体验；开发没有调用真实API、读取正式数据或替用户开启自动。实现依据见[架构与复盘](第十一阶段架构与复盘.md)，实际测试见[验证记录](第十一阶段验证记录.md)。
