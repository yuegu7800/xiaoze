## 结论

第五阶段的方向成立：本地记忆有了清楚的范围、维护入口和共用真实取数路径的解释。应继续保留小型本地JSON、最小证据、可更正和完整删除来源链。暂时没有理由换向量库、扩建人格状态机或提前接微信。

不过，初次交付的179项通过没有覆盖“多个资料共用一个来源”的维护边界，也没覆盖所有提交后显示错误。复盘实际重现了资料消失/假成功问题，已修复。下一阶段需要做，但应收敛为**召回相关性、解释准确性与用户主动多轮体验**；具体任务书见 `第六阶段开发提示词.md`。本轮只生成提示词，不执行下一阶段。

## 本轮发现与修复

| 问题 | 可复现场景 | 修复与限制 |
|---|---|---|
| 明确更正被静默丢弃 | 同句“我不喝咖啡，我喜欢简短回复”产生两条记忆；抑制咖啡后更正长度，旧记录被标更正但新记录因祖先被blocked而不安装 | 仅服务层对仍存在记录的明确编辑/确认允许维护安装；自动提取与重放仍受blocked限制，不删除或裁剪祖先ID |
| 确认候选后候选消失 | 先标记同源另一候选，再抑制第一条资料，确认候选会先移除pending，再被安装器静默跳过 | 同上，明确确认保留有效条目；已删除的记录不能通过此路径复活，旧原话仍隐藏 |
| 来源预算满时确认吞掉候选 | 同槽位同内容已有64源ID，确认另一来源的旧版候选 | 明确维护时超过64根上限抛CapacityError，事务不提交，候选和正式文件保持原样；自动提取仍保守忽略超限重复证据 |
| 有效记忆无法创建话题 | 有效长度记忆与被停止召回的咖啡共享旧原话；按memory创建话题被误认为重放旧原话 | 话题区分原话来源和有效记忆来源。原话用hidden_sources检查；有效记录按记录状态取数；明确撤回过的话题来源仍禁止重建，完整删除祖先继续保留 |
| 重复标记提示成功但没有新内容 | 同一轮、同一类别重复标记不同摘要，确定性ID/槽位冲突被静默忽略 | 明确提示已有条目，应从列表确认/更正，不写盘、不推进代次；不扩大成无限同源候选 |
| 提交后显示失败仍抛第二次异常 | 确认/标记已经保存，run内部刷新失败被捕获，但外围再次刷新导致回调异常或覆盖失败提示 | 准备视图、刷新、定位及渲染放到同一提交后保护区，提交只执行一次；保留“提交已完成但显示失败”结论 |
| 改人物/问题仍留下旧预览 | 预览主人后在预览页改成小林，结果仍像是新对象的查询结果 | 修改问题或预览人物立即清空旧报告；新报告标明场景/人物。只动控件，不改存储、epoch或last_trace |
| 反馈证据过长挤走输入/保存 | 合法32记忆依赖全部放进自动增高Label | 改为固定高度、可滚动只读文本，真实Tk在最大依赖样例下输入和保存仍可见 |
| 将累计依赖误说成本轮直接输入 | reply_trace融合了之前助手内容的祖先，原话可能已经不在本轮请求 | 改成“累计依赖，含经助手历史传递的来源”；明确不能据此证明本轮直接注入原文/资料或模型正确理解 |

维护例外不是给普通聊天开放绕过权限：`maintenance=True`仅用于已经通过场景/记录ID/状态校验的本地确认和编辑。抑制/删除后的原话防重放标记仍在；用户普通自称不能改主人，删除后的条目不能按旧ID找回。修正新资料的删除祖先仍指向原来源，关联删除照样清理它及派生回复。

没有修改主人温柔、尊重、默认善意和含蓄亲近的固定原则，没有依据合成文本追加更多人格禁令。本轮也没有改变运行时API、模型、密钥、正式存储版本或路径、来源预算。

## 仍存在、适合第六阶段处理的问题

直接在内存构造唯一咖啡偏好“我不喝咖啡”，调用现有真实recall函数：

| 查询 | 当前结果 | 判断 |
|---|---|---|
| 不太想工作，陪我说说话 | 选中“不喝咖啡” | 只因“不”字交集产生误召回，和眼前话题无实际关系 |
| 来杯拿铁怎么样 | 没选中“不喝咖啡” | 有饮品含义但没有共同字，存在漏召回 |
| 喝点什么 | 选中“不喝咖啡” | 原有有限饮品规则命中，应保持 |

这是离线检索行为证据，不是用户真实聊天效果，也不能据此宣称接入语义模型后就会变自然。本轮没有仓促改排序或堆同义词，交给第六阶段以小规模对照集、保守规则及真实请求捕获来改，避免为了一个例子损害其他偏好和范围。

另一个需要谨慎解释的问题是：某条资料没有作为本轮长期claims注入，可能已存在于本场景近期原话、人工话题，或有效助手历史中。当前预览已经分别展示这些渠道，但不能把长期区的“未选”直接解释成“模型绝对不知道”。累计reply_trace只能证明祖先依赖，不能代替直接输入清单。第六阶段可以先用不持久化视图把这些区别讲清楚；没有充分必要不新增完整请求或原文副本。

同源去重目前在长期排序/数量裁剪之后发生；多条近期重复记忆可能占用本来留给跨窗口资料的6条名额。当前是代码风险观察，尚未在本轮建立确定的体验结论；下一阶段必须先构造真实消息/预算路径复现，证实后才小改，不默认扩大预算。

建议有范围地继续第六阶段：优先召回相关性，保留取数/解释一致、范围隔离和不回流旧来源。没有新依赖、数据库迁移、自动抽取或付费批量评测的必要证据。开发代理仍用虚构数据；真实模型需要用户手动配置并主动发送，不能把之前的开发授权当作调用真实API授权。
