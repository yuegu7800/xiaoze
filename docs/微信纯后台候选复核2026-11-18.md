## 结论

发现值得优先验证的纯后台方向：Tencent/openclaw-weixin 的 iLink 微信机器人渠道。应修正此前只优先考虑独立 Windows 与 wxautox4 的候选排序：先有限验证官方渠道的私聊绑定与固定回复；普通微信群仍无已核实可用方案，不能由协议字段或第三方宣传推定可用。

本结论不是已完成接入，不自动启动开发、安装或外部操作。普通个人账号、机器人身份和绑定关系不可混称；新渠道不自动继承原账号好友、群或本机主人身份映射。

## 建议的最小下一步

先保留全部旧核心与桌面兼容层，不购买云机器或适配器。正式执行任务中先明确机器人身份及绑定入口，采用稳定版验证一个授权私聊的编号固定回复（不接模型/正式记忆）。若成立，再做最小渠道适配与稳定ID显式映射；原 prepare/commit/cancel、来源与删除合同必须保留。

微信群独立作为未解决项：只有实际收到群事件并回到原群才算成立。若服务端不提供，停止扩大群路由实现，转独立 Windows 环境候选。不为凑“完整迁移”同时启两个轮询者或重写人格。
