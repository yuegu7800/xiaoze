# ASTRA 第三阶段复盘与优化

日期：2026-11-11。范围：检查第三阶段现有实现，复现并修复有关草稿来源、时效、沉默与操作反馈的问题，为第四阶段准备任务书。本轮没有开始第四阶段，没有启动微信、后台主动调度或真实 API 调用。

## 结论

第三阶段已经具备“人工确认待续话题 → 本地判断是否适合 → 生成草稿或沉默 → 查看、复制、丢弃”的完整候选流程。本轮修复后，它更适合作为可控的本地试验入口。但它还不是能主动与用户连续交谈的人物：草稿不进入正式对话，普通回复也没有完整的派生来源链。下一阶段应先解决对话来源可信性，再打通本地开口和接话；不宜先增加定时发言、微信执行或更复杂的情绪系统。

主人关系方向保持不变：唯一主人是孤月大人，温柔尊重、默认善意理解、自然亲近。主人的出发点被善意理解，不等于每个事实判断都自动正确；小泽可以温柔诚实地表达不同看法。想安静时不打扰，也是温柔。普通聊天不能改变固定主人关系。

## 本轮发现和已完成修复

| 问题与复现 | 本轮处理 | 影响与取舍 |
|---|---|---|
| 草稿只记录主要话题来源，却可能使用近期其他发言和记忆；删除额外来源后，草稿还留着相关正文 | 记录实际送入候选请求的用户原话、记忆及话题来源；提交前复核所有依赖；相关来源失效时草稿失效 | 这是请求级保守依赖，不声称知道模型具体用了哪个词；可能使一份草稿较早失效 |
| 用户新说“今天想安静一点”，已生成的草稿仍能复制 | 成功提交新聊天后，当前场景待处理的私聊/群聊草稿失效并清空正文和反馈 | 公开草稿的素材独立，不随普通新对话失效；未成功提交的用户输入还不是已记录边界 |
| “我不是不想聊小说”、引用“晚安”、假设“先不聊”被关键词误判为拒绝 | 使用有限完整句式判断，排除引用、否定和条件；保持本地日期约束 | 只改善已知误判，仍非通用语义理解 |
| 群中小林明确停止，小乔再发言后，全群判断忽略小林 | 全群评估检查每位成员最后一条发言 | 保守尊重各人边界；不等于已经实现持久免打扰状态 |
| 旧草稿缺少完整来源，加载后仍可复用 | 策略版本升为 `local-candidates-2`；旧非公开草稿在有效视图中失效，正文/反馈清空，不猜测补链 | 仅加载不改文件，后续成功保存才持久化；旧公开草稿仍按其独立素材和期限校验 |
| 来源列表前50字相同会冲突；选择后难以确认全文；失败操作清空输入 | 来源带序号并显示完整选中来源，删除失败保留编辑；用途/对象显示改进为中文；丢弃公开草稿后清除已确认的旧素材显示 | 只改本地控件和回调，没有重做界面或修改实际剪贴板 |

候选来源上限为512个源ID、64个记忆ID，超限在联网前明确拒绝，不裁掉来源后继续生成。来源失效可在读取时立即阻止使用，不能把这一点说成立即擦除磁盘正文。关联删除则按既有提交流程清理。

## 仍然存在的关键缺口

### 1. 普通助手回复会成为未追溯的副本

使用临时虚构数据复现：用户说“我喜欢银色纸灯”，后续助手说“我记得你喜欢银色纸灯”。删除最初记忆及关联原文后，后续助手回复里的“银色纸灯”仍存在。普通对话以后可能再次读到它。这说明现有“关联删除”还不能覆盖普通助手文本的全部传播链，不能宣称信息已经在所有派生内容中消失。

本轮采取局部措施：私聊及指定群成员的主动候选暂时不使用旧助手回复，只使用有效用户发言、记忆、话题和关系，并明确不据此声称自己之前说过什么。候选准备时也不把人工话题标题当作新的用户自述来提取记忆。代价是候选更难判断自己是否重复问过，这需要下一阶段的可信助手历史解决，不能靠恢复全部旧回复绕过。

普通聊天来源链的修复会涉及一轮中的用户原话与助手正文分离、传递依赖、有界保存、旧记录兼容和删除预览，不能用全局字符串替换解决。本轮没有把这个存储变更塞进第三阶段修补，已把它设为第四阶段首要验收项。

### 2. 草稿与真实本地交谈之间缺一环

现在复制、预览都不等于小泽在对话中开口，这是正确边界。但用户看完草稿接着回答时，普通对话不知道那句话真正展示过。下一阶段可以增加用户明确点击“在本地对话中说出”：建立真实的本地助手消息，而不是伪造用户输入或微信发送回执。朋友圈草稿仍只保持草稿。

### 3. 分寸和自然程度尚无真实模型证据

- 人工标记主题、证据和方向的操作偏多，可先减少重复输入，再考虑自动候选发现。
- “这个话题不要再聊了”可能关闭当前人物/全群的多个话题，尚无细粒度指代消解。
- 最新一条发言的停止判断不是稳定的免打扰状态；持久边界需要明确状态和解除方式。
- 丢弃草稿会清除附属反馈，负面体验样本也随之消失。若需要保留复盘，应让用户显式保留有界、可删的简短评价，不暗藏原文档案。
- 话题相关性仍是有限字符规则；没有证据表明应该立即引入向量库、每轮模型抽取或自主兴趣成长。

这些限制要在体验中分别观察，不能以“增加人设提示词”代替数据流和交互修复。

## 验证与真实状态

## 第四阶段的顺序和体验材料

建议按“普通生成内容可追溯 → 真实本地助手消息 → 最小话题操作优化 → 虚构体验与交付”推进。先用银色纸灯的多跳派生用例验证删除，再让用户体验小泽在本地开口后接话、主人善意分歧、朋友不同边界、群内对象隔离和不打扰。真实模型测试由用户主动触发，记录具体失败片段与期望，不能自动批量消耗 API。
