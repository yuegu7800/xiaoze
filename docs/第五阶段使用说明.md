正式本地记录位于 `C:\Users\ZhuanZ\Documents\Codex\wechat-acheng\.local-xiaoze`。模拟是 `simulation-v2.json`，模型试聊是 `state-v2.json`。文件名保留兼容，内部版本仍为3。勾选独立体验区后，按脚本、模拟/API、长期记忆开关及话题开关使用另外的文件。重开时选回相同组合才能看到相同资料；换模式看到空库不代表原库丢失。勾选前的普通试聊中，开关只改变取用，不会变成另一份库。

## 记忆面板

在目标模式、场景和人物下点“记忆 / 证据”。顶部显示模拟/API、普通/独立体验和场景；人物下拉框明确查询范围。只查询当前场景，不会搜同一昵称的其他私聊。群内可选某位成员或全部成员。

- **记忆与维护：** 默认看当前有效资料，可切“待确认”“历史 / 到期”“全部状态”或具体状态。类别和正文/最小证据关键词可以组合；输入关键词后回车或点“搜索 / 刷新”。条数同时显示筛选结果、本场景全库容量、候选及来源标记占用，区分“没有任何记忆”和“当前条件无匹配”。
- **详情：** 选择条目看易读类别、来源、时间、期限、证据原话及位置、更正前后关联和排查用ID，不再直接展示整段JSON。自述、维护者改写与旧版待审核来源分开标注，不把确认当成外部核实。
- **人物概览：** 按上方人物组合当前有效资料和固定关系，不受关键词或类别筛选影响。临时覆盖会注明。暂无资料时如实显示，不推断性格、不计算好感，也不另存一份传记。孤月大人始终是唯一主人，温柔尊重的关系规则不能通过普通记忆编辑改写。
- **标记候选：** 从近期用户发言选最小连续片段，填写内容、类别后加入候选。成功后会显示来源人物的待确认列表；选中再确认。确认后切回有效列表并保持原ID。助手自己说过的话不是新的事实来源。

维护使用单条明确ID。更正时，先选条目、点“更正内容…”或“偏好改变…”，在下方输入框改写，然后“保存所绑定条目的修改”。筛选和刷新不会把编辑转绑到另一条；原条目不在可见选择中时拒绝保存，输入保留。重新选回原ID可继续；要改另一条请明确放弃旧编辑或同意替换。写盘失败保留输入，不报告成功；已经提交而显示失败会单独说明，应刷新或重开查看。

容量满时，可以先处理候选并删除不再需要的条目。**确认候选不减少总条目数，停止召回也不释放条目容量。** 写入时沿用原有有限历史整理规则。来源去重/撤回标记另有10,000个ID上限，删一条记忆不一定释放这些标记；不要手工删标记使旧来源复活。若这些预算确实用满，应整理并规划新的独立本地存储，而不是无限增大上限或承诺普通删除一定解决。

## 离线召回预览

进入“离线召回预览”，在其独立人物选择与问题框中输入，例如“喝点什么”“你记得我的偏好吗”，点“本地预览（不联网）”。此操作不占普通聊天输入，不联网、不回复、不抽取新资料，也不执行输入中的“停止话题”指令。暂停中或正常生成在途时仍可只读查看。

结果复用普通聊天实际取数路径，显示：

1. 哪些有效资料将作为长期内容注入；哪些已有同源近期原话，不再重复注入。
2. 哪些因为待确认、到期、停止召回、更正/替代、临时覆盖、无足够字符关联、数量或字符预算未选中；开关关闭也明确显示。
3. 哪个人工话题被选中，或因为状态、等待时间、相关性及单话题上限未选；它不是人物事实。
4. 哪些近期原话和助手历史纳入/省略，旧助手来源未知、依赖失效、近期字符预算或完整来源链预算不足分别说明。基础来源本身放不下时说明整次请求会在模型调用前被拒绝，不假装已提供资料。

预览是带时间的**当前快照**，不是上次请求的精确回放，更不是模型内部思维。实际点击发送还会处理新输入的明确自述/停止表达，时间、修改和新消息也会改变取数。预览不覆盖上一轮召回信息、不变更文件/代次/话题/草稿/期限/冷却；刷新维护面板后清空旧预览，需主动重新取数。不为了显示排除原因去读其他场景。

长期正文最多6条、1,800字符，近期正文16,000字符；来源链另受128根ID、32记忆ID、16话题版本预算限制。它们是不同预算。当前相关性是字符规则，不等于懂所有同义句；库里有资料但查询词不同，仍可能未选。

## 更正、停止召回与删除

| 操作 | 含义 |
|---|---|
| 更正 / 偏好改变 | 保留原历史，建立维护者提供的新有效版本。旧原话失效不会误伤正确的新结论；删除祖先仍完整保留 |
| 停止召回 | 条目和正文仍在磁盘，相关来源不再取用；不是物理删除 |
| 删除长期记录 | 删除条目/证据，清理相关话题、草稿、派生助手正文和反馈；近期用户原话仍保留（当前撤回规则也过滤旧来源） |
| 预览关联删除 | 先显示同源闭包中的记忆、原话、助手、话题、草稿及反馈影响；明确确认后删除这些内容，保留后来的无关用户文字 |
| 近期窗口淘汰 | 旧普通原话离开12条窗口，已明确保留的最小记忆仍可能存在；不是完整语义遗忘 |

来源不明的旧助手正文不能猜测补链，破坏性删除会保守清理本场景这类正文及反馈。v1已知原件/备份如已纳入管理，仍按已有规则清空整个目标场景；跨文件清理失败报告未完成，可重试，不承诺断电原子性。v2顶层旧文件仍只读，须用原按钮明确升级；本阶段没有自动迁移。删除不代表清除提供方、手动复制或系统备份。

## 反馈与费用

“记录体验”保留原有表达标签，另有“记错了 / 记着但本次未选中 / 已提供但表达生硬 / 没有对应资料”。它们是你的评价，程序不会把当前预览冒充过去那轮的诊断。界面另外显示选中轮次已保存的记忆依赖ID和原话来源数，来源不足的旧记录明确说明。曾提供不等于模型正确使用；没有长期ID也可能从近期原话得知。

复盘后这部分明确标为**累计依赖**，包含通过之前助手消息传递的祖先；不能用它证明本轮直接注入了对应原话/记忆，也不能证明助手复述了所有祖先。证据区固定高度可滚动，较多ID不会挤掉反馈输入和保存按钮。修改预览人物或问题后旧报告即清除，须重新点击预览。

继续只保存有界标签、一句期望和既有版本/轮次绑定，最多30条，随轮次淘汰或关联删除；不新增失败原文档案、整库副本或完整请求日志。写期望时只需必要信息，不要填写Key。

查看、搜索、概览、预览、维护、采用和反馈不调用模型。模型试聊发送、通过本地门槛的显式候选评估才可能调用一次服务并计费；配置由你当次填写，开发没有读取或改变已有地址/密钥/模型。请求会把角色设定及选中的上下文/记忆送到你配置的服务，**本地存储不等于完全离线推理，也不是每次上传整个库**。暂停不能撤回已经发出的请求，无自动重试。

已实现和虚构模拟通过的是查看、取数解释、维护及交互路径；真实模型的自然、温柔、主动分寸和长期相处尚未验证。自主学习、性格成长、后台开口、持久免打扰和微信执行均不在本阶段实现范围。
