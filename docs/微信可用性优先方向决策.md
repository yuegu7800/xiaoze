# 微信可用性优先方向决策

2026-11-15。响应用户“思考应该做的方向”。本轮是方向复核，仅阅读项目源码、开发文档、微信可执行文件版本元数据及公开项目文档；没有修改业务代码、启动微信、读正式配置/Key/聊天/记忆、安装接入组件、调用模型或发送消息。

## 推荐方向

保留小泽人格、记忆、分人关系和主动表达核心，把“用户正常使用电脑时，小泽能持续在原会话正确收发”设为下一项唯一交付目标。先证明接入通道可用，再接模型，之后在实际相处中改表达。当前OCR加全局键鼠路线仅保留兼容/诊断用途；不再把扩充该路线的局部测试作为后台能力进展。

优先复用成熟且能明确说明适用版本的适配器，不自研个人微信协议。对最多一两种具体候选进行有限可行性验证；候选如需购买/登录，先取得明确兼容与试用依据。若没有可验证的原生后台接入，采用独立虚拟机/备用电脑隔离桌面，是释放用户主机鼠标的现实过渡；虚拟机不是后台协议，内部仍需要可操作桌面、不能休眠，断开远程连接后的行为也必须实测。它也不能替代群私路由验收。

“不干扰用户主机”和“无需图形桌面、可在服务器无界面运行”是不同能力。当前首先交付前者，后者只有具体通道证明可用时才承诺。若用户主机关闭后仍要持续运行，需独立常开机器或合适服务器；在主机上的虚拟机随主机关机停止。

## 最小验证及继续/停止条件

1. **具体兼容性门槛。** 明确候选版本、当前微信版本或独立测试环境版本、登录方式、群私功能、桌面依赖、授权费用。不能证明则不编写核心迁移代码；不为了试适配器改动用户日常微信。
2. **不用LLM的实际收发。** 独立机器人账号、一个用户私聊和一个小测试群；在用户明确授权的测试会话内，只响应约定测试标记并返回固定编号文本。先证明群问回群、私问回私和多轮持续；无需API Key、正式记忆或付费生成。安装/登录/发送是后续明确执行任务，不由本轮方案自动开展。
3. **实际干扰与故障验收。** 用户在主机浏览网页、移动鼠标、打字；群私交错消息；相同内容重复发送；断线重连；目标切换/窗口关闭。检查是否串发、漏收、重复、抢焦点和不确定后盲重发。UI接入在隔离环境中验证宿主机不受影响；不宣称测试有限轮数等于长期保证。可先做10–20条可核对编号的交错测试，再让用户短期日常试用，避免一开始要求大量人工验收。
4. **接回既有核心。** 仅增加实际需要的入站事件转换、场景绑定、串行处理和出站结果映射；先被动文字回复。稳定后恢复已有群参与/主动表达，再收集少量真实例子改人机感。AIRI形象语音、表情、朋友圈排在稳定文字使用之后。

提前停止：不支持当前环境且无可行独立环境；必须占用户主桌面却无法隔离；无法可靠区分群/私目标；发送不确定仍自动重放；需要未核实第三方服务但无法取得明确接入条件。出现这些情况交付具体阻塞与替代选择，不自行开启下一轮人格/架构任务来充当进展。即使没有费用上限，也不能无限尝试无新增证据的分支。

## 代码复用范围

character_service.py的prepare_exchange和提交/取消、memory_store与关系、wechat_character.py的群成员上下文/多人取数/主动表达可保留。RoutedTransport、MultiRunner、OCR MessageCursor与标题校验属于窗口轮询耦合，不要求新事件接入伪装成“切窗口再读”。后台路线不能只替换send_text。

现有场景和人物含显示名派生键。若新接入提供稳定chat_id/sender_id，必须由本机显式绑定到既有场景/主人身份；不把同名即同人、不全局替换旧键或自动搬库。没有真实稳定ID就诚实采用适配器可提供的身份强度，不伪造账号认证。

IntegratedModel准备结果是单份；初版使用有界串行事件处理，避免并发reply撤销另一个会话的准备结果。事件reply_target在接收时固定，不能取当前活动窗口或最新发言者决定。保存发送结果沿用已有准备/提交合同，提供方accepted、按键尝试、实际送达必须分别描述。无需先造新代理框架、消息总线或大型统一SDK。
