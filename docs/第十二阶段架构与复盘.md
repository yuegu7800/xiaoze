# 第十二阶段：自动开口状态与体验闭环

## 实现前小设计（2026-11-12）

按用户指令执行第十二阶段任务书，不重验旧阶段、不改变自动时机/配额/人格。相关当前基线78项通过，ASTRA第十一阶段3条Tk回归通过；项目无`.git`，不初始化仓库。开发仅虚构/mock。

1. 从自动策略`due`提取纯判定，在只读状态和实际调度中共享。保留原顺序：调度缺口→关闭/在途/环境→夜间→空闲→未回应→请求/采用配额→核心话题门槛。只有调度入口更新检查时钟及note，展示不调用due/activity。
2. 从`check_candidate`提取共享核心门槛结果，旧tuple接口及原诊断文案保留；新增只读投影返回固定状态码、说明/一步操作、必要时间边界与epoch，不返回正文、来源标签、配置。区分扩展未启用、待确认/尚未到时/无有效话题、待处理、冷却、明确安静等。
3. UI只持有当前范围的一份派生元数据。Core/范围/开关/epoch/暂停/在途改变，或最早到期、not_before、冷却、午夜等时间边界到达时才重取。普通倒计时最多约每秒绘制，用注入时钟，不增加每秒快照/磁盘访问/记忆遍历；时间回拨也使缓存失效。停用/切范围/关窗清空派生条目。
4. 空闲及滚动小时取单调时钟，夜间与核心到期/冷却取既有北京时间；剩余下限0。会话上限无恢复倒计时，不鼓励重启绕额度。达到时间只代表可等下一次检查，不保证生成或开口。
5. 当前状态与历史执行事实分开：原主提示区保留实际完成结果。必要时只在当前自动会话保留一个结果类别和提交epoch，用于明确的合法silent提示；不含正文/配置/动态来源标签，停止、换范围/新活动清理，显示时还需匹配当前epoch。没有自动历史档案。
6. Core→策略→预算锁顺序与原run/slot/commit ticket/draft_id/采用事务不变。只读访问必须通过完整状态/文件不变和在途并发用例验证。保留第十一阶段与ASTRA故障恢复断言。

## 最终实现

`opening_state.py`提供不可变的`WaitState`与`CandidateState`，只含固定状态码、固定文案/操作建议、必要时刻和epoch。没有I/O、正文、来源ID、动态来源标签或配置。时长向上取整、下限0。

`auto_opening.py`的`_condition`由实际`due`和只读`projection`共享。`due`仍独立负责last_check及恢复空闲等原调度动作；投影不调用due/activity。保留原先的门槛顺序与请求/采用时机；小时限制从已有时间戳计算恢复时间，会话限制不提供恢复倒计时。输入等暂缓刚解除、但尚未被原environment入口确认时，投影只解释“等待重新计时”，不提前显示可以评估，也不替调度重置时钟。在途提示不声称模型必已调用；模拟明确不调用API。

`activity.py`的`candidate_condition`与原`check_candidate`兼容包装共享核心门槛。原候选事务继续使用check_candidate；顺序仍为扩展启用→待处理草稿→冷却→用途/开关→明确安静→有效话题。区分未确认和未到时只补充同一门槛的说明，不创造话题。扩展未启用时，原实际评估仍按原API抛ValueError；状态读取只给出启用提示，不更改原行为。

`activity_service.py`的`candidate_state`复用可写性/范围校验、只读snapshot过期投影和共享核心判断；兼容的candidate_precheck委托它。读取不占请求槽、不保存、不触发新冷却或证据刷新。paused/inflight仍阻止预检。生成和采用各自的提交核对、epoch、具体draft_id、来源失效和提交凭据均保留。

`local_chat.py`在原控制区展示“当前条件 + 剩余时间 + 一步操作”和一行已有预算数量。100ms poll仍负责原环境同步和队列；仅显示部分约每秒绘制，操作和真正tick可即时绘制。自动帮助文案补充“需人工确认话题”。`activity_panel.py`及手动发送启动失败沿用ASTRA清理，只补明确的错误停止分类。

## 只读和刷新边界

这里的只读是状态取数/判断不修改业务状态；Tk绘制会更新标签与两个UI派生字段。正常poll的原environment同步仍可能重置空闲或作废在途资格，那是原调度行为，不是读取状态的副作用。

UI临时缓存最多一份当前binding的元数据投影，校验Core/选择/开关、epoch、paused、inflight、存储版本及当前时刻。最早记忆/话题/草稿到期、not_before、last_check+600秒、北京时间午夜或时间回拨使其失效。保守地在任意Core事务epoch变化后重取，即使变化发生在别的场景；不新增细粒度失效框架。缓存没有复制正文或配置，停止、范围改变、关窗时清空；真正生成从不使用这份缓存作提交依据。

只在自动策略已通过其门槛时需要核心投影。普通空闲/小时/夜间倒计时直接读时钟与既有预算；不每秒做核心快照、磁盘读写或记忆遍历。实际30秒预检保留原取数，可能与边界显示各取一次，未为此更改事务。Tk实测同一有效边界内反复50次强制绘制，额外snapshot为0；epoch变化、时间回拨、到期各重新取一次。仅证明这些场景下的取数行为，没有进行耗时/CPU性能基准，不声称性能提升。

单调时钟管理空闲、调度缺口和请求/采用滚动小时；北京时间管理夜间，Core既有时钟管理冷却、话题到时/到期和午夜安静语义。生产时钟同源，测试可注入。倒计时可能因时钟变化重算，达到0仍待真正tick与全部其他门槛。超过90秒缺口先显示恢复等待，真正due再重新计时。

重复读取测试比较完整memory.state、文件字节、epoch/paused/inflight、last_trace/last_notice/请求证据、自动策略字段与预算/回应门槛；均不变。另用线程阻塞mock completion验证：在途读状态后可正常提交；维护来源后迟到仍取消。Core→策略→预算锁顺序保持，展示不在持有策略锁时请求Core。

## 当前条件与完成事实

自动控制区是当前首要阻止原因，不是历史请求清单。原主提示区显示本次实际完成结果；后续状态刷新不覆盖它。待处理草稿不会被当作刚调用模型，本地门槛阻止不新建冷却、不占自动请求次数。

新增的唯一短期完成收据是一个`(model_silent或simulation_silent, commit_epoch)`：只有本次自动事务明确成功返回silent且有提交凭据时才写入，用于冷却期间准确说明模型/模拟沉默。仅当前自动会话内存中一条，无正文、配置或动态来源标签，不写盘；活动、启动下一次评估、停止或新会话清理，显示还必须与当前Core epoch一致。任何新事务epoch改变后不再把旧沉默归因到当前状态。它不是历史档案，也不从现有last_check或草稿重建历史。
