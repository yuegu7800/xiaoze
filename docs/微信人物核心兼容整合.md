# 微信完整版与小泽人物核心的兼容整合

2026-11-13。接用户“逐项兼容整合”的要求继续实施。本轮沿用完整微信程序，把已有核心接入实际消息路径；没有重新搭建机器人，也没有替用户启动微信或真实API。

## 现在如何使用

关闭旧小泽程序后，仍双击桌面“奇思妙想 / 启动小泽微信”。API地址、模型、Key、群名、昵称和原启动方式不变。三个会话模式继续可用：孤月私聊、指定群聊、群聊＋孤月私聊。先检查一轮预览，再由用户启用实际回复。

收到新文字后，可打开“关系与动态 → 小泽记忆、逐轮反馈与话题”。选择私聊或群聊，再选中具体一轮：

- “评价所选回复 / 本轮取数”：打开原反馈窗口，看中文摘要或技术详情，然后保存本地评价。只有已提交回复可评价，预览不算说过。
- “查看、纠正和删除记忆”：打开原记忆维护窗口，可筛选、确认、改写、停用、删除及做只读召回预览。管理的是微信版实际使用的同一个Core，不是另一套测试资料。
- “把所选原话保留为待续话题”：手动选择连续原话、标题和待续方向，确认后成为当前人物的话题；普通聊天相关时才选入。
- “管理待续话题”：暂停、重新启用、结束或删除并撤回。删除会使依赖该话题的回复失效，不是只把标题藏起来。

“人物关系与记忆”“朋友圈文字草稿”等原工具保留。本地试聊入口、已保存资料与后期本地活动能力也保留，不把它们当作微信新增发送授权。

## 实际结构与数据流

`app.py`显式连接时创建`wechat_character.make_model`；双会话把同一factory传给原`MultiRunner`。原`PrivateRunner/GroupRunner`负责接收、去重、参与判断、路由和发送；新组合适配器复用`CharacterCoreBase.prepare_exchange`组装一次请求，生成结果在发送前检查是否仍有效。模型地址、模型名、Key和原网关选项沿用旧配置，不新增调用来抽取、重排或润色。

普通流程：新文字 → 固定范围与人物 → 共用核心的选择性取数/生成 → 原参与和暂停门槛 → 检查核心版本/来源到期 → 原发送操作 → 提交核心 → 写原兼容归档。群合并批次最多8条/4000字；此前发言为无回复的用户轮，最后一位对应本次回复。近期组装前仍裁在12条，不把批次当成扩大窗口的理由。长期和来源预算不变。

主动流程沿用旧时间与次数门槛，只把上下文交给核心。没有新用户发言时不执行自述抽取，不把本机调度指令保存为用户原话；安静/明确结束可提前沉默。普通群插话继续由旧参与策略控制，不等于新的全天后台生活。

主动事件在已知多人群中标记面向全群；只有一名已知发言者时仍按原存储规则保守标记该人物，不为标全群虚构第二名成员。角色决策与原生操作分开，发送前及慢路由/标题检查后的最终门槛都会检查准备结果是否仍有效；不持核心锁跨原生I/O。

## 文件、首次兼容与删除范围

运行时每个实际会话使用`data/character-wechat/wechat-private-<摘要>-v2.json`或`wechat-group-<摘要>-v2.json`，内部仍是v3。群/私聊文件、Core和来源分开；群成员ID复用原PeopleMemory的本机显示名映射。每个会话的人物清单有界128人，角色由固定ID与原关系配置决定，不从聊天正文或档案文本决定。新增本文件内`wechat_people`清单和`wechat_seeded`一次性兼容标记，没有另建人物服务、向量库或后台进程。

首次使用只在内存暂存旧归档尾部24条中的用户发言，保留最多12条原话；原发言时间未知，在实际请求中用`recorded_at=null`明确表示，不把导入时间冒称发言时间。未知来源的旧助手正文留在原归档，不伪造来源链后自动注入。原群人物库的teasing/tone/length稳定边界以`legacy_review`兼容资料进入核心，证据是旧资料快照，不是伪造的用户原话，处理时刻也不是原发生时间。为防删除后旧原话绕回，保守关联同一人的导入原话作为可能删除祖先；不宣称每条原话都直接证明了旧结论。

成功的正式提交、有效live观察或明确本地维护后，兼容数据、人物、标记及计数随同一次核心保存；以后不再从旧归档和旧人物库反复导入。D批次收紧为独立候选视图，超出人物/记忆容量的旧项有界不接纳并显示原因/数量，不清库、不自动补回；具体顺序及暂存合同见[微信整合D批次说明](微信整合D批次说明.md)。D仅实现和静态审查，仍待E动态验证。原归档继续作为兼容记录保留，新增完整请求使用核心过滤后的数据，不拼回原`history`和SQL检索内容。

**核心“删除来源”会删除该核心里的来源原话、相关记忆/话题及依赖回复，清除瞬时取数证据；不会删除旧`memory.json/group-memory.json`或旧SQLite兼容归档。** 原副本保留不等于物理全副本删除，但不会再自动导回模型请求。界面和记忆维护窗均明确这一范围。没有修改或清空既有`.local-xiaoze`。

两份文件没有跨文件原子事务：核心是新增请求的权威来源。若发送操作返回后核心写入失败，暂停、不发布成功轮证据、不自动重发；若核心已提交而旧兼容归档随后写入失败，保留已经提交的核心及证据，明确报告兼容归档未完整写入，不回滚成“没说过”，也不重发。发送操作返回仍不证明微信接受、对方收到或已读。

## 取消、证据与界面

预览不提交核心新对话/记忆，不写原聊天归档；原预览文件行为保留。群内只听不说在正式模式保存各人实际输入，不保存候选回复。生成失败/截断、暂停、更正或删除后的迟到结果不发送，不登记成功轮。发送前检查到期与来源有效性；检查通过后已经进入的原生发送不能被承诺撤回。

普通成功轮的证据来自实际同次组装，只有ID/状态/版本等原有元数据，不另存请求/Key/全文。反馈与维护复用原控件和提交逻辑；绑定捕获的Core、场景、原人物与完整turn ID，不凭当前模式下拉框改身份。新成员加入时场景句柄稳定；切轮不转绑未保存评价；窗口断开时关闭这组工具、清证据，防止旧窗口覆盖重连后的核心。话题与证据只读显示不联网。
