# 小泽第四阶段：可信对话与本地开口

日期：2026-11-11。双击项目目录 **启动小泽本地试聊.cmd**，使用原有Python环境，无需安装新依赖。已经打开的旧窗口请先关闭再启动。本阶段没有微信连接、监听、发送、发布和后台主动调度。

同日复盘修订已应用：手动更正后能正常继续聊天，群内临时偏好的过滤统一，暂停再开启话题不会恢复旧版本助手内容；普通完成回调遇显示异常会说明保存结果并继续处理后续事件。完整结论与下一步建议见 `ASTRA第四阶段复盘.md`。

## 从一次本地开口开始

1. 默认“流程模拟”不联网，结果有显著模拟标记，只验证操作。选择主人或虚构朋友，输入“虚构小说纸船的结尾还没想好”，发送到本地试聊。
2. 打开“话题 / 主动草稿”，启用本场景话题。选一条近期用户来源，在原文预览中用鼠标选中1—160字，点“用上方选中片段作证据”。程序填入证据和可调整的主题、方向，不自动提取或联网。
3. 调整主题/方向，核对归属与期限，点“标记并确认”。也可沿用“加入待确认话题 → 确认”的两步流程。群来源可明确选择面向全群，不能分配成另一人的自述。
4. 到“看看小泽现在想说什么”，选择私聊/群聊用途和对象，点“评估一次”。她可能沉默；本地能判断不适合时不调用模型。通过判断后最多一次生成请求。
5. 选择有效草稿，点 **“在本地对话中说出”**。它作为独立的小泽消息加入对应本地时间线。没有生成假的用户发言，也没有微信发送。
6. 关闭话题面板，继续输入“我想试试你刚才说的方向”。下轮上下文可以看到有效的本地开口消息。这个按钮不清空你原来写的输入草稿。

采用不额外调用模型。预览、评估和复制仍不把草稿写入对话；只有明确采用才建立本地助手消息。准确含义是“已加入本地对话”，不是用户已读、双方同意、现实经历或外部发送。朋友圈草稿不能通过这个动作加入私聊/群聊，也没有发布按钮。

## 时机、重复点击与失败

沿用每场景一个待处理草稿、10分钟评估冷却、最长30分钟草稿期限，依赖话题更早到期则取更早期限。采用不重置评估冷却，不增长好感或延长话题寿命。丢弃仍暂停同源话题；无后台自动再评估。

采用前重新检查用途、对象、来源、期限、暂停、上下文代次和在途请求；新对话成功后旧非公开草稿失效。切换用途/对象导致旧视图票据失效时请刷新并重新核对。窗口内生成、候选和采用共用单请求边界。

同一草稿重复采用只返回原消息位置，不再次添加。采用后草稿正文被移走，草稿只保留有界元数据；已采用消息不会因原草稿30分钟过去就消失。仍受近期容量、来源有效性和删除规则约束。

写盘失败时正式文件和内存不变，输入保留。若已经提交但刷新显示失败，界面会明确说明；刷新或重新打开从已提交记录恢复，同一草稿不会再次新增消息。不要把文件提交与界面绘制理解为一次跨资源事务。正式启动器防止重复开窗；绕开启动器的多进程写入仍不受保护。

## 记忆失效和删除的实际含义

新普通回复和采用的助手消息具有来源记录，覆盖实际提供的用户发言、注入记忆、话题版本和先前有效助手内容的传递来源。它是保守的请求级依赖：资料曾出现在请求里就可能影响整段回复，不能精确判断哪一个词受影响。因此一条资料变化可能让多条回复暂不进入模型。

修订后的来源区分“实际读到的原话”和“更正后有效的维护资料”：旧证据失效不会把正确的新结论也判为失效；全部根ID仍供明确关联删除使用。旧来源记录保守兼容，读取不改文件，新生成采用来源子版本2。没有额外迁移按钮或新增完整备份，不用旧程序降级写入。候选策略现为 `local-candidates-4`，旧非公开草稿需按当前条件重新评估。

| 操作 | 现在的行为 |
|---|---|
| 停止召回、更正、替代、到期 | 记录可保留供维护；相关旧原话和派生助手内容不再作为当前上下文使用。不是物理删除 |
| 删除长期条目 | 删除条目、相关话题/草稿、派生助手正文及其反馈；近期用户原话保留，所以模型仍可能从这条原话理解信息。相关旧原话当前也受来源撤回过滤 |
| 删除关联原文及派生内容 | 预览原话、助手正文、记忆、话题、草稿和反馈影响；删除相关用户原话和多跳助手派生正文，保留后来无关用户发言 |
| 删除话题 | 删除话题和草稿，清理依赖此话题版本的助手正文及反馈；原始用户发言/记忆保留 |
| 清空当前场景 | 清理本场景用户原话、助手正文、记忆、话题、草稿、公开素材和反馈，保留无正文防重放标记 |

若同一条长期记忆合并了多次自述证据，关联删除按现有源ID闭包包含这些共同来源，预览范围可能超过一条发言。之后由用户主动重新提供的文字是新的独立证据，可以重新记录；不会按字符串全局删掉所有相同词语。助手自己转述不成为新的人物事实。

旧助手记录没有来源链，不能知道它是否复述了被删除资料。因此破坏性删除会保守清理本场景所有来源未知的旧助手正文和相关反馈，同时保留不属于所选来源的用户原话；界面先说明这个范围。删除不是语义词语审查，不承诺清理不受应用管理的副本、手动复制、服务商、系统备份或磁盘残留。

来源失效时历史消息位置仍可保留，界面显示说明并不送入模型；正文已删除时显示占位，不把它冒充完整历史。仅因停止召回而保留的正文仍可能在磁盘，不能说成已经擦除。

## v2升级与路径兼容

文件继续放在 `.local-xiaoze/*-v2.json`，**文件名保留，内部结构现在为version=3**。没有自动移动路径、改快捷方式或替换历史原文。

新文件直接用v3；已有v2仅只读加载，加载不写文件，也不推测旧助手的来源。请在对应普通/独立体验模式点击 **“升级v2来源记录”**，确认范围后原子替换该模式文件。升级保留原话、记忆和旧助手正文，不新增完整备份。旧助手文字标为维护历史，不进入模型；新回复开始记录真实来源。

升级失败保持旧正式文件和内存。旧代码无法理解v3，不能再降级写入。未知版本/损坏格式保留原件并报错，不自动清空。v1仍通过原明确入口导入；v1原件和已知备份的破坏性清理沿用第二阶段整场景规则，跨文件失败会报告未完成，并非断电原子事务。v2需先升级再做写入/删除，不能绕过只读限制改管理副本。

## 容量、费用与体验

近期最多12条容器：普通一问一答占1条，独立助手开口也占1条；正文窗口不是永久全文档案。近期请求正文预算16,000字符。每个生成内容最多追溯128个用户源ID、32个记忆ID、16个话题摘要版本；优先保留当前用户、近期用户和有效资料。加入旧助手历史会超来源预算时，在请求前完整省略这条助手内容，不截断来源后继续发送。基础资料本身超预算则不请求模型并明确报错。

这限制了历史传播链大小，代价是长对话中部分助手历史会缺席；不是自主遗忘或总结。长期记忆256条、待审核32条、证据每条最多64源ID、话题32条、草稿历史24条及既有撤回标记上限继续有界。草稿还保留原格式兼容上限，但新生成实际受更小的共享来源预算约束。

切换“模型试聊”才使用你本次填写的接口/模型/Key。发送普通聊天或通过本地门槛的候选评估会联网；采用、升级、话题操作和反馈不联网。Key只在窗口内存，不读取旧配置、不保存。暂停无法撤回已发出的请求，可能仍计费；没有自动重试或模型切换。

新增三组第四阶段体验脚本，只载入文字、不自动发送。勾选独立体验区可隔离模拟/API和开关对照。在“记录体验”里可以选择本地开口消息，记录“接得自然、重复追问、时机不合适”等标签和一句期望，最多30条并随关联消息淘汰/删除；草稿已有反馈采用时转移到消息，不保留正文副本。丢弃草稿仍不保留负面反馈摘要，本阶段没有另建评价档案。

人格与主人温柔基调保持固定。真实模型的温柔、自然、接话与不打扰还需你主动体验；本阶段开发只用虚构数据和模拟网关验证。
