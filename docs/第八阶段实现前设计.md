# 第八阶段实现前小设计

日期：2026-11-11。217项现有相关基线本轮通过（10.124秒）。已核对原聊天render/show_feedback：正文无逐条动作，默认新开反馈取最后一轮；已有窗只lift，不定位新选择。以下为本轮计划，最终状态见交付记录。

1. 原Tk Text回复后添加“评价这条回复”tag。映射仅保留Core引用、原场景、稳定turn ID、原speaker ID、模式标签；每次重画使用不复用的动作编号，解绑并释放旧Tk回调。点击时重新检查原Core/场景及轮次资格，不能从正文/序号/当前人物重建身份。映射随最多12条原近期记录保留；原轮失效时原poll清理。关闭释放映射。
2. 复用唯一FeedbackPanel。明确点击按稳定ID选择；原按钮仍可用。反馈改为非模态，以便回主聊天点另一条。相同Core/场景保留原单份草稿防转绑；跨范围且有未保存内容时拒绝替换，提示先保存/放弃。无草稿时关闭旧窗再开正确范围，不建立多份草稿缓存。
3. 原固定高度证据区域放两个标签页：“中文摘要”默认、“技术详情”按需。两者共用该轮feedback_view，摘要是固定文案和已有数量/状态映射，详情保留原全部ID。清理、切轮和显示失败同时作用于两页。不再recall、不复制正文、不联网、不增加持久字段。必要的本地采用target仅从现有轮次投影到瞬时view，避免把全群开口显示为只面向主人。
4. 不改召回/人物提示，不测模型自然程度。沿用原三组体验与临时推窗样例；指引增加逐条反馈，以及梗含义/自嘲/嘲讽对象的人工观察示例，不引词库、识图、表情发送或上游代码。与上一轮项目建议衔接只限这些说明。
5. 单元回归核对实际元数据及只读、稳定选择和错误范围；临时Tk走真实Text动作、切轮草稿、跨模式/场景、失效/淘汰、长证据和保存失败路径。重跑原217项、关联Tk脚本、中文启动器--check及导入边界。所有夹具为新临时目录的虚构资料。

缓存仍仅进程内，资料维护/到期等保守清理策略不变；不增加历史诊断存档、依赖或数据迁移。无真实样本时交付“真实语言效果待验证”，不自动进入第九阶段。
