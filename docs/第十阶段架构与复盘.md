# 第十阶段架构与复盘

## 实现前最小设计（2026-11-12）

当前基线：240项单元测试通过（含配置加密3项），全部为虚构资料/mock。当前目录无`.git`，不初始化仓库。

- 使用原Tk `after`每30秒检查，策略对象注入单调时钟与北京时间；默认空闲10分钟，23:00—08:00安静。超过90秒未检查视为休眠/阻塞恢复，重新等待，不补跑。
- 两个开关每次启动关闭；会话绑定实际Core对象、模式、体验区/检索开关组合、场景ID和人物ID。停止/切范围使独立代次失效；输入、子窗、最小化取消当前运行资格并重置空闲。自动刷新不计用户操作。
- 进程内共享有界配额：自动模型请求尝试2次/滚动小时、6次/程序会话；自动采用同上。手动请求不计其中。失败/沉默/迟到不退还请求尝试；本地门槛与配置校验失败不计数。用户未成功回应前最多一次开口，手动采用也设此限制，重新开启不清除。
- 新增只读核心预检，复用`check_candidate`，不写盘/推进epoch/更新冷却。实际评估仍占原`request_slot`并再次校验；在调用completion的实际边界校验取消及预占配额。
- 自动评估额外接收纯策略guard，生成前/提交前在Core锁内核对。提交返回在同一锁内捕获的commit ticket；请求槽释放后，只对该次draft_id使用此ticket采用，绝不刷新ticket恢复资格。自动采用前再次检查代次、空闲、夜间、输入/子窗与未回应限制，调用原`adopt_draft`，成功后才记表达次数。
- Tk控件只在主线程访问；工作线程只使用冻结绑定、策略状态与原Core事务，通过原事件队列返回。停止不能撤回已发HTTP；已提交未采用草稿保留原生命周期，不补采用。异常停止自动会话，不暂停普通聊天，不自动重试。绘制失败只恢复持久记录。

## 最终实现与事务边界

新增`auto_opening.py`，包含冻结`Binding`/`AutoRun`、轻量策略和进程共享配额。没有新增依赖、数据迁移、持久调度字段、全文日志或请求档案。默认常量按任务书保留：600秒空闲、30秒检查、600秒原候选冷却、滚动小时2次/程序会话6次，夜间23:00—08:00。额外明确90秒调度缺口为恢复阈值，约三轮检查未执行时重新等待。

范围绑定使用实际Core对象、场景ID、人物ID、模型/模拟模式、独立体验选择和检索开关组合。资格还有自动会话代次、用户活动版本和自动采用开关版本。身份核对固定`local-owner`/`owner`和实际private/owner角色，不用显示昵称认证。自动仅覆盖这一范围；其他原手动候选用途未变。

`local_chat.py`新增两个默认关闭的开关、醒目停止按钮和状态。开启才建立30秒`after`；原100毫秒事件队列轮询只观察输入/窗口环境，不调用模型、不读取候选正文、不推进冷却。键盘/鼠标操作与输入修改更新活动版本；自动render、反馈刷新不更新活动时钟。所有存在的子窗口都使自动暂缓，不仅是模态窗口。API配置变量改变也关闭自动，避免已开启会话悄悄换服务。Tk访问仅发生在主线程，工作线程拿到的是绑定、配置副本和纯策略回调。

生成链路：

1. 主线程检查启用/绑定/环境/夜间/空闲/未回应/配额，再调用`candidate_precheck`。预检在Core锁内对`memory.snapshot(compatibility=False)`的到期投影复用`check_candidate`；不启用扩展、不写文件、不推进epoch、不设置last_check。
2. 实际生成复用`evaluate_candidate`、原`request_slot`与Core锁，重新检查原候选条件。自动专用guard在组装前和保存前核对独立代次/活动/夜间/调度缺口，不修改普通手动候选行为。
3. completion包装先本地校验冻结配置，再在Core锁内检查原ticket/暂停/自动资格，并在共享预算锁内原子预占请求尝试。随后走原`ApiCompletion(json_object=True)`。合法silent、错误、超时、取消都不退款；门槛阻挡和配置验证失败不占次数。模拟没有HTTP尝试计数。
4. 候选保存后，在同一个Core锁内返回`commit_ticket`及具体`draft_id`。普通手动调用返回形状保持不变；commit ticket不持久化，也不是新的诊断字段。退出`evaluate_candidate`后原请求槽已释放，工作线程才把结果放入原UI队列。
5. UI处理该次运行，在Core→策略→预算的锁顺序内重新检查资格、夜间、开关版本、未回应和采用配额，使用返回的commit ticket调用原`adopt_draft`。不取“最新草稿”，不调用`core.ticket()`为采用刷新资格。期间维护/手动采用/普通发送推进epoch时，旧凭据失败；结果保留原生命周期，不补采用。
6. 只有原采用事务真正成功返回后，才记自动表达次数和等待回应标记。随后绘制失败也不会重做事务。重复UI队列事件因运行已结束直接忽略，原采用收据继续防重。

HTTP不能被停止开关撤回。Core锁决定生成/采用提交与维护的先后；提交后的用户操作只取消后续自动采用，不回滚已经提交的草稿。本地输入始终保留。任何生成或采用的模型/格式/IO错误停止自动会话，不给普通聊天调用pause，不自动重试；取消不是新请求排队。

## 计数、回应与生命周期

请求与采用时间戳各自最多6条，独立总量和滚动窗口计数只保存在进程内，开关/切范围不清零。主界面明确“本次程序会话”和“滚动1小时”，不称总费用或每日预算。手动请求不计自动请求；自动模拟采用计表达次数。共享状态没有正文，回应标记以弱引用关联实际Core，避免配额对象保留已关闭Core的数据；手动采用收据去重最多128个ID。

`activity_panel.py`在原采用事务之后、绘制之前通知等待回应；重复采用收据不重新设置标记。成功`exchange`在工作线程提交后通知，只有正确Core/场景/人物的新成功聊天才解除等待。输入编辑、反馈、复制、切换、自动采用和重开开关不能解除。首次开启还检查实际对话最后事件，避免程序重开后直接追着未回应的手动开口再说一句；删除不被当成新回应。

草稿/采用仍使用原来源链、话题revision、记忆删除/更正/抑制/到期、12轮容器和预算。没有添加普通exchange的瞬时证据，也不改变累计祖先语义。原JSON对象参数、官网DeepSeek非思考与2048上限、普通聊天1024、沉默对象协议、静态空白/截断诊断和DPAPI配置全部保留。

## 验证发现与取舍

新增`test_auto_opening.py`的22项测试和`smoke_stage10_auto.py`实际Tk流程。完整262项单元测试通过；原阶段相关Tk脚本通过，详细命令见验证记录。

Tk测试发现新增控制后原聊天区请求高度过大会挤掉最小窗口输入/按钮；将聊天文本控件请求高度降为4行，剩余区域仍自动扩展。实际820×680下聊天区98像素、输入区71像素，发送和停止自动均可见。未为演示缩短真实默认间隔。

既有故障测试会用未执行构造器的LocalChat或SimpleNamespace测试旧反馈/绘制路径，新增可选自动钩子兼容这些测试壳；没有删除或放宽旧断言。新增测试本身的夜间模拟最初跳过30分钟草稿有效期，已改为22:59:59→23:00:00以单独验证夜间采用门槛。

无真实付费调用、正式库读取、微信操作、系统任务或新模型配置。本阶段的真实自然程度、10分钟频率是否合适和长期体验仍待用户选择开启后观察；通过数量不能替代语言效果。未覆盖全部DPI/系统休眠组合，也未增加跨重启预算、系统后台调度、其他人物自动模式。第十阶段完成后停止，交回Codex/ASTRA复盘，不进入第十一阶段。
