# 小泽第三阶段：待续话题与本地主动候选

> 本文保留第三阶段交付记录。当前代码已进入第四阶段，存储升级、有效助手历史与“在本地对话中说出”的用法请看 `第四阶段使用说明.md`。

双击项目目录的 **启动小泽本地试聊.cmd**。仍使用现有Python环境，不需安装新依赖。第三阶段没有微信连接、监听、发送、朋友圈发布或后台主动调度。

2026-11-11复盘修订已应用。已打开的窗口请关闭后重新启动以加载修复；人物设定、API配置和已有文件路径没有迁移。独立复盘见 `ASTRA第三阶段复盘.md`。

## 先试一条待续话题

1. 默认“流程模拟”不联网，只验证操作；切换“模型试聊”才会使用你在窗口填写的API。密钥只在进程内，不读取旧配置、不保存到文件。
2. 选择主人或虚构朋友，发送一条虚构文字，例如“虚构小说里的纸船结尾还没想好”。
3. 打开 **话题 / 主动草稿**，点击 **启用本场景话题与草稿（兼容v2）**。每个场景分别启用，这一步只保存本地结构，不联网。
4. 在“以后可以接着聊”中选近期用户发言或有效记忆，填写其中一段连续证据（1—160字）、主题（1—100字）和待续方向（1—200字）。有效期限可选1、3、7天，最早再考虑时间可选0、10、60分钟。
5. 点击“加入待确认话题”，选中条目，再点击“确认 / 明确重新开启”。群内来源可以明确勾选面向全群；否则归属来源发言者，不能改成另一人。
6. 普通聊天里提到相关主题时，最多带入一个有效话题；不相关时不注入。可以编辑、暂停、结束和删除。编辑或结束会使旧草稿失效。重新开启不延长期限。

这一步是人工选择，不是小泽自动形成了新兴趣。音乐、游戏仍是可调整的人物设计；你的偏好不会自动变成她的偏好。保存的话题只证明本地对话或资料提到过这件事，不代表真实共同经历。记忆来源使用当前有效记忆内容作最小证据，标明人工维护；不会冒充原始用户逐字自述。

普通聊天有限支持“这个话题不要再聊了”“不聊了”“先到这里”等明确停止短句，关闭当前人物及全群相关的可继续话题；引用、条件和玩笑不据此关闭。复杂表达可能不识别，请手动结束。群里一位成员明确停止时，全群话题采取保守关闭；没有细分成“其他成员还能继续”的策略。

## 评估一次，而不是自动发言

在“看看小泽现在想说什么”选择用途和对象，然后点“评估一次”。

| 用途 | 允许的材料 | 结果 |
|---|---|---|
| 私聊草稿 | 当前私聊用户发言、选定对象的有效话题与资料 | 本地草稿或沉默 |
| 群聊草稿 | 当前群用户发言、选定成员资料，或明确的全群话题 | 无需在虚构原话中点名，也可产生本地候选；不接微信群 |
| 朋友圈草稿 | 本面板专门输入并确认的公开素材，以及独立公开角色设定 | 不检索私群偏好、不发送私群历史的公开草稿或沉默 |

公开用途先在专门输入框中填写最多600字并点“确认以上为公开素材”。记忆或话题的确认不等于公开授权；程序不会自动把它们复制进去。没有公开素材时本版本直接沉默，没有强制生成泛泛动态。清空输入并再次确认会撤回素材和相应公开草稿。

本地先检查：启用状态、有效话题、对象、安静边界、最近明确结束表达、未处理草稿、期限与冷却。能直接判断不适合时不调用模型，因此没有Key也能看到这些沉默原因。通过检查后才可能调用一次模型；模型也可选择沉默。流程模拟会产生有显著标记的合成草稿，不评价人物效果。

引用、假设或“我不是不想聊”不因包含停止关键词而直接沉默；全群评估分别查看各成员最后发言。规则仍有限，复杂边界请用明确停止或手动暂停话题。为了防止已删除的信息从旧助手回复进入候选，当前私聊/指定成员候选暂时不读取旧助手回复；它对自己是否重复问过的判断因此有限。

默认每场景最多一个待处理草稿，私聊、群聊和公开用途共享该场景的名额与10分钟评估冷却。冷却从成功提交草稿或模型沉默时开始；本地提前沉默和失败不延长它。它表示评估频率，绝不表示发过消息。时间使用Asia/Shanghai；重启不重置冷却。草稿30分钟到期，依赖话题更早到期时取更早时间。

丢弃话题草稿会清掉正文与反馈，并暂停相同话题，避免换个说法继续推销；需要明确重新开启，或从新发言建立新话题。丢弃公开草稿会撤回这次公开素材，需要明确重新提供。到期不同于拒绝：到期后在话题仍有效、冷却已结束的情况下可以重新评估。

## 复制、反馈与失败

选中有效草稿查看对象、用途、来源、期限、模型和规则版本；点“复制所选有效草稿”才写入剪贴板。**复制不表示发送、发布或发生过共同经历**。没有确认已发送按钮。草稿不进入聊天历史、人物事实或其他话题的证据。

公开草稿生成后可以由你手动决定是否在外部使用，小泽不知道实际执行情况。单次复制即使本地时间记录写盘失败，剪贴板可能已经改变；界面会报告未完成，不会自动重试，更不会执行发送。

选中草稿可记录时机合适、打扰、话题硬转、重复追问或草稿冒充已发生，并填写最多300字期望。反馈附在该草稿内，不复制整段聊天，随草稿失效、删除或容量淘汰移除。模拟和真实模型体验分开，不能把模拟回复当作自然程度证据。

普通回复和候选共用一个在途请求。你可以继续写聊天草稿；候选回调不清空输入。面板顶部也有暂停/继续，关闭面板会作废仍在生成的候选。修改话题、来源、切换用途/对象/场景/模式或完成新的对话，都会让迟到的旧请求失效。已发出的HTTP请求无法撤回，可能仍计费。不自动重试，不切换接口或模型。

成功提交新的对话后，当前场景已有的私聊/群聊待处理草稿也会失效并清空正文和反馈，避免继续复制不合时宜的旧话。公开素材独立，不受普通新对话影响。草稿记录实际请求中所有用户原话和记忆来源，不仅是主要话题；任一相关来源失效，都可能使整份草稿失效。

候选模型须返回明确的草稿/沉默JSON；无效结构、额外范围字段、空正文、超长、截断与网络错误不作为草稿保存。提供方省略finish_reason时沿用第二阶段的兼容接受，不能保证远端未截断。

## 对照体验与人物关系

“召回长期记忆”关闭的是长期资料的注入与召回，**不关闭第二阶段明确偏好的提取和保存**；近期对话仍在。关闭后也不使用待续话题。“话题延续”可独立关闭，不影响普通长期偏好召回。两者都不阻止你在专门公开输入框主动提供素材。

建议勾选“独立体验区”，相同脚本分别使用有/无长期记忆、有/无话题延续；本版本按这些开关、模拟/API与脚本分文件隔离。旧第二阶段的独立体验文件没有自动导入或移动，新版本使用带topics/no-topics后缀的文件。普通state/simulation文件名保持不变。

新增脚本覆盖主人善意分歧、话题与拒绝、群参与与公开草稿，只载入输入、不自动发送。观察：小泽能否自然接住具体事情；是否对主人温柔而允许诚实分歧；是否尊重沉默；是否反复追问；是否把私事带到公开草稿。真实模型体验由你主动运行，开发阶段没有调用真实API。

唯一主人为孤月大人，默认善意理解、温柔尊重和含蓄爱慕的规则固定，不随话题、互怼偏好或互动次数下降。群内主人和朋友按本地测试身份分别处理。全局人物设定会说明主人的存在，但朋友自身不会继承主人身份；公开草稿使用另行维护的公开设定，不发送主人关系资料。

## 本地文件、兼容与删除

沿用 `.local-xiaoze/*-v2.json`。顶层仍为v2，新增可选的场景字段 `activity`，其中独立 `version=1`。没有该字段的旧v2正常加载、普通聊天正常使用；只有点击启用才在该场景写入扩展。启用、写入采用原子的整文件替换，写入失败保留之前的正式文件，不新增完整v2备份。未知扩展版本/损坏资料报错并保留原件，不静默重置。不要同时运行旧版程序改写已启用扩展的文件。

每场景最多32条话题（含结束、到期状态），满后请删除不用的话题；最多24条草稿元数据历史，新增时淘汰最旧非待处理草稿及其反馈。话题删除撤回标记最多512个源ID，满时拒绝操作，不丢防重放标记。数值均为可调整设计选择。没有定时清理线程，查看、复制、评估、读写时检查到期；后续成功写盘才持久化计算状态。

| 操作 | 新话题与草稿的影响 |
|---|---|
| 记忆不再召回 | 相关话题失效但保留供维护；旧草稿正文与反馈清空，不能复制 |
| 更正、替代、到期 | 旧来源对应话题/草稿失效，不继续用旧结论生成；不会自动把旧话题迁到新结论 |
| 删除长期条目 | 移除该条目来源所关联的话题、草稿和反馈；近期原文仍按第二阶段规则保留，操作前提示 |
| 删除关联原文及派生内容 | 预览原文、记忆、话题、草稿数量，按来源移除相关正文和反馈，保留无正文防重放ID |
| 删除话题 | 删除该话题、它的草稿与反馈；原始聊天/记忆仍在，撤回ID阻止同源再次标记 |
| 清空当前场景 | 移除近期原文、记忆、话题、草稿、公开素材和反馈；保留必要来源ID，若再次使用扩展须重新启用 |

近期窗口淘汰不等于主动删除：人工选择保留的最小话题证据可留至到期，未经选择的整条原文仍只保留最近12轮。话题、草稿不能成为隐藏档案或删除后恢复的副本。

复盘后策略版本为 `local-candidates-2`。旧非公开草稿因来源不完整不再可用，有效视图清空其正文和反馈；原话题保留，按正常条件可重新评估。旧公开草稿仍检查独立素材及期限。仅加载不会重写文件，状态在后续成功保存时落盘。草稿最多关联512个源ID、64个记忆ID，超限明确拒绝生成。

**尚未修复的普通聊天限制：** 后续助手回复可能复述之前的用户信息，而这类普通回复尚未保存完整派生来源。删除原始记忆/关联原文后，后续助手文本中仍可能残留该信息并被普通聊天再次使用。上表不能解读为覆盖所有普通助手衍生文本；本轮已阻止它进入主动候选，完整修复列为第四阶段首项。不要把当前关联删除理解为全库语义擦除。

若模式曾明确升级v1，破坏性删除仍先清空管理中的v1原件和已知备份的整个当前场景；新扩展没有额外备份。跨文件中途失败报告未完成，支持重试，不承诺异常断电下整体原子性。新扩展启用后该模式不再允许导入v1；要升级旧v1请先在空白v2模式通过既有入口完成，再启用扩展。

所有记录、素材、草稿和反馈只供本地使用，不上传GitHub。删除不承诺清理模型服务端、手动副本、系统备份或磁盘取证残留。真实自然程度、长期自主性和微信执行仍未验证或未实现。
