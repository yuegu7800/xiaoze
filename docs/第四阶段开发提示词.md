## 三、先修普通生成内容的来源与删除

### 3.1 可复现的问题

建立虚构场景：用户说“我喜欢银色纸灯”；后续助手回复“我记得你喜欢银色纸灯”；删除最初记忆及关联原文后，后续助手正文仍可能包含该信息，并被普通聊天重新送入模型。现有候选隔离只是局部措施，不是普通聊天根治。

先为这个问题及多跳传播写行为回归，再选择最小存储方案。不能通过固定词替换、只删源回合或永久禁用所有新助手历史来宣称解决。

### 3.2 来源模型和范围

至少在语义上分开用户原话和生成的助手正文，即使它们仍共享一轮容器。给生成文本记录实际请求中可见资料的依赖，包含用户来源、有效记忆/版本、话题，以及已使用的助手消息的传递来源。不同来源类型和场景必须明确，不把模型回复当用户自述。

可以使用保守的请求级依赖，不要求模型逐句证明自己使用哪个词。须说明：这可能撤销一段其实没有复述旧信息的助手回复，是可信性与上下文保留之间的取舍。人物配置版本与用户内容来源分别管理，不因固定主人设定存在而把全库对话串成一条删除链。

来源追溯要有界：明确正文、元数据、依赖边、撤回标记与近期窗口的容量和生命周期。不得不断把全部历史源ID累计进每条新回复，也不能在超限时悄悄截断依赖并继续生成。选择可解释的预算、拒绝或安全裁剪策略，先裁掉相应上下文再构造请求；裁剪与删除是不同含义。不要为本阶段引入图数据库、向量服务或通用事件平台。

### 3.3 失效、删除、旧数据与并发

- 停止召回、修正、替代和到期：旧结论及依赖它的助手内容不能继续作为当前事实注入。允许保留维护用历史，但应明确不可用于生成，不能把“不召回”说成“已删除”。
- 删除长期条目：清理该条目和依赖其注入的生成内容；用户近期原文是否保留沿用并明确说明原有语义。仅删除长期条目不等于删除用户在近期亲口表达的信息。
- 删除关联原文及派生内容：清理相关用户来源、助手派生正文、话题/草稿/证据/反馈与管理中的副本；应覆盖多跳助手复述，不让摘要和反馈成为隐蔽副本。保留必要无正文防重放标记。
- 不因同轮助手正文受到影响就静默删除这一轮后来的无关用户原话。删除预览分别说明原话、生成消息及其他内容的影响。若独立用户后来主动重新表达相同偏好，它是新证据，不用全局字符串匹配误删。
- 旧记录没有派生链，不得猜测或伪造历史来源。明确采取保守隔离、标为旧资料等兼容策略，说明旧助手历史的召回和删除限制；需要破坏性清理时提供本地明确动作与范围预览，不能悄悄删除旧场景。
- 生成期间删除、抑制、修正或到期必须影响提交前复核；迟到回复不能提交失效来源内容。沿用单请求、锁、代次、原子文件替换与失败保护。

按必要性选择可选扩展或新版本，不预先强制v3。变更会影响旧写入程序时必须版本化，旧文件只读加载不自动重写；明确迁移入口、可复现样例及已知v1/v2副本清理边界。未知版本或损坏文件保留原件并报错，不重置。不要增加不会一起清理的永久全量备份，也不承诺跨文件断电原子性或取证级擦除。

来源能力完成后，主动候选可恢复读取经过校验的新助手历史，以减少重复提问；旧未知来源回复仍不能直接重新放回。普通回复与候选应复用同一取数/来源收集路径，避免两套规则再次漂移。

## 四、让有效候选成为一次真实的本地开口

在现有话题/草稿面板增加明确动作，例如 **“在本地对话中说出”**，仅用于私聊和群聊。保持“评估一次”“预览”“复制”和该动作分离，生成或复制仍不自动写入正式对话。

点击采用前重新检查：当前场景和对象、草稿状态/期限、来源有效性、上下文版本、暂停状态、在途请求和重复采用情况。失效时说明原因，不为了采用暗中再请求模型。沿用有界数据存储，不创建另一份长期全文日志。

采用成功后，应以独立助手消息出现在对应本地聊天时间线上，随后用户输入能自然接话。不要造出一条“用户：请主动说话”来凑成现有问答轮结构，也不要伪造用户已经回应。群聊显示消息面向全群还是指定成员，后续发言者仍由可信控件确定。

持久化本地助手消息、消费草稿和必要关联应为一次一致提交，同一草稿连续点击、重启或迟到回调不产生重复消息。写入失败不显示成功，不清空用户正在写的输入。文件提交和Tk绘制不能假装具备跨资源原子性：若提交成功但渲染失败，应可从已提交事件恢复显示，不再次创建事件。准确标为“已加入本地对话”，不声称用户已阅读。

本地助手消息意味着小泽在这个本地界面确实说过该句话，可以为下轮“我刚才说的”提供对话依据；它不证明现实经历或用户认可，更不是微信发送/朋友圈发布。模型文本不能自行创建执行记录。朋友圈草稿不提供此采用动作，仍保持未发布。

采用的正文保留原草稿的来源和版本，并参与第三节的删除传播。避免同时永久保留草稿正文和消息正文；若短期保留双方，删除和到期语义必须一致且有界。已采用消息不要因原草稿30分钟期限自动被误认为“从未说过”，但其失效事实不能继续当当前事实召回。解释“发生过本地消息”与“内容仍有效”的区别。

“本地说过某句”不自动成为对方偏好、双方约定或共同现实经历。尤其不能从助手自己的提问抽取对方认可，不能因采用次数提高好感或自动延长话题寿命。用户实际回答之后，才按既有证据规则处理新自述。

## 五、最小体验优化

继续使用现有窗口和CMD入口，不重做UI。减少人工标记的重复工作：选中近期用户消息即可查看原文、选择最小连续证据、填写/调整主题和方向并确认。保持证据长度限制、归属校验和人工确认；不要一键把整段原文变成长久记忆。第三阶段已解决同前缀来源冲突、全文预览和失败保留输入，保留这些能力。

这一阶段优先把现有手动流程做顺；自动建议主题只是可选项，只有不增加隐藏联网、来源清楚且仍待确认时才考虑，不为凑功能实现通用提取或自主兴趣学习。

保留现有反馈标签和版本记录。对本地主动消息补充“接得自然、重复追问、时机不合适”等必要入口，允许记录一句具体期望；容量有界，关联来源和删除策略明确。若提供丢弃草稿后仍保留评价的功能，必须由用户显式选择，仅保留必要评价并可单独删除，不能保存被删除的正文或通过自由文本暗藏整段聊天。该增强不是核心交付的前置条件。

不在本阶段全面重写话题指代消解或持久免打扰状态；对“一个停止短句可能关闭多个话题”等现有限制如实说明，有明确可复现小修可做，大范围重构留给复盘。

## 六、必要验证与体验材料

开发只用虚构数据和模拟响应，检查实际送入网关的内容、持久文件及重启行为，不仅断言提示词包含某句话。至少覆盖：

1. 银色纸灯的源消息 → 助手复述 → 再次助手转述；关联删除后，下次普通请求和候选请求都没有已删除信息。相关持久正文/反馈按删除语义清理；同轮无关用户原话保留。
2. 修正、停止召回、到期、仅删除长期条目、删除原文及派生内容分别符合说明。覆盖原始来源退出近期窗口、被助手继续引用、依赖达到容量边界和重启。不可默默断链，也不可把窗口裁剪当永久遗忘。
3. 用户后来独立重新提供相同信息可作为新来源；助手重复该信息不能自我制造新证据。旧无来源记录按兼容策略处理，不虚构补链；未知版本和写入失败不破坏原文件。
4. 采用有效私聊/群聊草稿后只新增一条真实本地助手消息，没有假用户输入。接着回答时网关看到正确顺序和对象；群内另一成员响应不改变原对象归属或主人身份。
5. 预览/复制仍不新增对话事件；公开草稿不能采用成本地私群消息或发布记录。重复点击、重启、暂停、切换对象/场景、关闭面板、来源删除/过期以及新上下文发生变化时，不误采用旧草稿。
6. 模拟提交前后失败，包括文件写入失败、提交成功而显示失败后的恢复；不双写、不重复说、不丢输入、不触发网络重试或外部操作。候选和普通请求在途时的冲突规则明确。
7. 主人私聊、群内主人和朋友身份规则保留；朋友声称X_A、要求改主人无效。私聊暗号不进入另一私聊、群聊或公开请求。记录层隔离通过不等于真实模型永远不会口误。
8. 来源修正/删除发生在慢响应期间时，普通回复和候选均拒绝失效提交。原有话题暂停、冷却、沉默、公开素材隔离及第二阶段行为继续可用。
9. 真实临时Tk控件完成“选择来源 → 确认话题 → 评估 → 本地开口 → 用户接话 → 反馈 → 删除”的流程；模拟网关和剪贴板。CMD启动检查与新入口导入边界通过，不加载微信适配层。

准备少量固定虚构体验脚本，由用户主动运行真实模型：

- 主人说“我是为了你好”但存在具体事实分歧：观察善意温柔而非机械同意。
- 小泽接续小说话题主动开口，主人回答，她能接上且不重复问同一问题。
- 主人表示想安静；朋友另有边界，关系不串人、不以主人身份覆盖拒绝。
- 记忆更正后再次谈起；无法确认旧事时坦诚，不拿旧助手自述证明自己记得。
- 群内小林和小乔接不同话题，公开草稿不包含任何私聊暗号。

脚本只加载、不自动发送，继续隔离模拟/API、场景和对照开关。自然程度由具体多轮体验和用户反馈评估，不使用字数、关键词或测试数量作为“像真人”的分数。没有真实体验也可交付实现与模拟验证，但明确待验证项目。

## 七、交付与停止条件

推荐顺序：阅读和基线 → 复现普通派生缺陷 → 最小来源/兼容设计及实现 → 删除/失效回归 → 本地独立助手消息与幂等采用 → 简化话题操作 → UI验证和体验材料。第一部分未解决前不要抢先实现新的主动执行功能。

不需要泛泛重搜开源。现有架构足以先完成最小版本；确实复制代码或引入依赖时才核查当前上游、许可证、NOTICE、数据流与维护信号，引用真实来源，不把过去研究当作本次已核实。默认不增加第三方依赖。

交付至少包括：

- 可直接启动的本地入口，更新 `docs/第四阶段使用说明.md`，说明采用、费用触发点、消息含义、删除区别、兼容/迁移与限制。
- `docs/第四阶段架构与复盘.md`：最终来源模型、范围、容量、消息生命周期、请求及删除数据流、失败语义、关键取舍和开源复用情况。
- `docs/第四阶段验证记录.md`：实际运行命令、结果、失败复现及修复、未验证项；历史测试只作基线。
- 给6 ASTRA ULTRA的材料：普通来源链是否闭合、有界方案的损失、旧数据如何处理、实际本地开口是否自然、用户应体验的场景和下一步建议。明确区分已实现、虚构模拟通过、真实用户/模型验证过、仅设计。

若普通删除仍不能覆盖某种派生路径，应直接列出未解决范围和原因，不能声称来源链已完整。不得把人工采用称为全天自主生活，把本地助手消息称为微信发送，或把剧情和模型推断当共同现实经历。

完成第四阶段后停下来交付，不启动微信、不启用后台主动调度、不自行扩展到第五阶段。
