# 自动开口前最小验收清单

日期：2026-11-12。用户已反馈候选修复后“测试可以”，记录为真实用户报告，不代替逐项结果。沿用原本地入口和已有白话指南，不需要重做第一至九阶段。

后续状态：用户明确说“验收可以”，同意推进下一步，已整理`docs/第十阶段开发提示词.md`供T3执行。以下作为历史验收参考，不能要求用户重新逐项通关。自动能力尚待第十阶段实现；本清单本身未启动任何调度。

## 先试最关键的两项

1. **开口后能接着聊。** 在现有候选中选一条有效私聊草稿，点“在本地对话中说出”，关闭面板，发“你刚才说的那个方向，我想试试”。观察她能否接住具体内容，而不是重复之前的问题；查看聊天中是否只出现一次开口。采用只是本地事件，不发微信，不额外调用模型；你的接话发送会调用一次模型。若这条已经试过，不必重做。
2. **结束后不继续追问。** 有效人工话题还在时，聊天发送“这个话题不要再聊了”，回话题页看是否结束、已有待处理草稿是否失效。再评估时应无有效候选。已有冷却、其他话题或待处理草稿会掩盖原因，不能仅凭列表空白判断停止成功。想单独测试“我想安静一点”，在另一个没有待处理草稿且不在冷却的独立练习场景中，先准备有效话题，再发送这句话，检查明确的安静状态/原因。本功能匹配有限明确表达，不承诺所有含蓄说法都识别；遇到漏识别就记录具体句子。

## 然后按需试三项

- **记忆修正。** 使用“主人：偏好与更正”：说“我不喝咖啡”，再说“更正，之前说错了，我喝咖啡”。记忆面板当前有效结论应更新，之后“帮我想一种喝的”应以新结论为参考。刚说过也可能从近期上下文获取，不能据此证明跨很久的长期记忆。不要为了推过近期窗口跑十几次付费请求。
- **分人关系与范围。** 用“朋友：不同边界”，扮演小林说“别怼我”、小乔说“可以接受友善玩笑”，再由孤月大人发言，观察尊重边界且主人态度温柔。用“记忆：私群隔离”的虚构暗号检查不从小林私聊带到群或小乔私聊。身份由本机选择；这不是微信账号认证测试。
- **合法沉默和失败。** 有待处理草稿时再次评估应提示先处理；冷却时应解释10分钟门槛。模型也可返回合法silent，这是一次成功评估但可能计费，区别于空正文、截断或格式错误。模型不会保证某次一定沉默，不必为了观察silent反复消费请求。网络/存储故障、暂停取消、重复采用和来源删除已有离线/mock回归，不需要用户故意断网、损坏文件或重复计费验证。

任何一项不自然，点那条回复旁“评价这条回复”，写一句具体期望；反馈只是本地记录，不会自动训练。不要求提交整库或Key。用户报告、模拟通过和实际观察到的具体行为分别记录。

## 后续自动化的建议范围（尚未实现）

用户意向是后续免手动点击主动进行。本轮仍不启用后台请求。下一步如开发，先限制为“本地窗口打开、用户主动开启的会话内自动开口”，复用现有话题、人物范围、冷却与草稿/采用事务；窗口关闭停止、不默认为系统常驻服务。自动评估和自动加入本地聊天是两个不同开关，前者可能计费，后者影响本地上下文，不能混称自动发送。

实现前应明确：只允许哪些场景/人物、空闲多久考虑、夜间安静时段、每小时/每天模型请求上限及表达上限、一键停止与下次启动默认关闭。定时醒来不等于每次都调用模型，本地条件不合适就不请求。合法沉默也计入请求预算；失败不自动重试。现有10分钟冷却只限制频率，不是费用或全天打扰上限，不能直接当完整自动化策略。

自动化需要额外模拟可控时钟验证：输入/生成在途不插话、场景切换不串绑、停止/删除/更正取消迟到结果、同一候选最多采用一次、沉默/失败不忙循环、关闭窗口和暂停立即停止后续排程。以上目前仅为后续设计要求，不是已具备能力。本清单不是下一阶段执行指令，也未生成或启动第十阶段。微信投递、好友和朋友圈发布继续留到最后。
