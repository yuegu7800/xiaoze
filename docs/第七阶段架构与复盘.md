# 第七阶段架构与复盘

日期：2026-11-11。

同日ASTRA复盘补充：已修复未保存反馈跨轮转绑、反馈保存取消在途生成、旧来源未知被写成确定零/原话数三类问题。详见 `ASTRA第七阶段复盘.md`；本轮217项回归与四个相关Tk脚本通过。下文是本阶段初次交付设计与记录。第八阶段仅提供任务书，尚未实现。

## 实现前的小设计

普通exchange在同一次messages组装时取得diagnostics，立即投影成仅含ID、时刻、版本、开关、通道和有限状态码的局部暂存。不再次召回，不保存正文、quote、动态匹配词、配置或请求。状态码描述实际分支，不代表模型理解。

每个Core独立缓存，每个场景最多跟随12条近期容器；以成功提交的turn ID绑定实际发言者。只有save_scene成功后登记。模型/格式/IO/迟到取消均不登记，不覆盖已有成功轮次。窗口关闭显式清空，重启不恢复。候选/本地采用本阶段不增加同等级证据。

普通反馈保持缓存；维护和活动写入默认保守清空该场景。exchange仅在记忆/话题/撤回等资料状态不变时保留之前证据；资料变化时清空旧证据再登记新轮。缓存只另存资料状态摘要hash，读取时与到期投影比较，不在只读查看中清缓存、推进epoch或写盘。到期时隐藏不再可信的证据，下次写入物理淘汰。近期淘汰按现存轮次修剪。资料hash不是全文副本，也不代表历史直接内容。

原记录体验窗口绑定创建时的Core/场景。选择项仅显示轮次ID、固定本地人物和时间，不缓存原话摘要。复用原UI轮询刷新打开的反馈窗口：删除/维护后清已显示证据，所选轮次消失则清空选择，不转绑另一轮。证据区域固定高度滚动，保存反馈不持久化取数缓存。提交成功但绘制失败时保留已提交标记，禁止再次提交。

本进程证据、历史累计依赖、当前快照预览分别说明；缺缓存只降级，不能重新取数补历史。来源ID不证明助手正文复述祖先内容，也不证明模型注意到或理解。详情如需查看仍到原记忆面板看当前条目，不在此复制正文。

## 实现与验证

已按上述设计实现。新增 `request_evidence.py`（白名单投影/固定理由码/显示）、`feedback_panel.py`（从原反馈流程提取的小UI类）、`test_stage7_evidence.py` 与 `smoke_stage7_evidence.py`。更新人物服务、原窗口、草稿反馈的缓存保留策略、体验提示、临时样例标题和原入口说明。没有新依赖、存储字段、文件副本、数据库升级或接口配置改动；没有改人格、关系规则、召回规则、预算或旧测试断言。

`_exchange`使用 `snapshot(compatibility=False)`，避免兼容偏好视图额外召回；实际messages只做一次recall。diagnostics与provenance在同次组装捕获，白名单投影后丢弃诊断对象。原用于持久topic_id的第二次relevant_topic也改为读取同次diagnostics选中的版本ID，避免重算选择。原reply_trace v2和旧v1语义保持。

缓存结构为Core独有随机ID、`scene -> turn ID -> {stamp, evidence}`。stamp是当前场景记忆、blocked、话题、撤回和公开源的SHA256摘要，用于保守检测资料变化；不缓存其正文副本，不写盘，不用hash推断内容。evidence包含版本、组装时刻、身份/轮次、开关、各通道ID、完整累计依赖、每条资料/话题的状态码、近期选择与预算标记。动态理由不保留，匹配词片段为零；依据码最长为21字符，不会把被删的词从理由再显示。

容量直接受既有容器限制：每场景最多12份；每份最多256个资料状态、32个话题状态、12条历史选择；直接长期最多6、直接用户/助手各最多12；完整依赖仍最多128源/128原话祖先/32记忆/16话题版本，ID沿用原160字符上限。没有另建无限计数、事件队列或错误档案。打开反馈小窗只持有这些元数据的有界显示副本，销毁时释放；不是新的原文仓库。

`_save`默认在成功存储后清该场景缓存。普通exchange与两种反馈显式允许保留，但保留项还必须匹配stamp、存在于当前12容器且reply_available；新成功exchange随后登记自己的暂存。来源/资料在生成中到期仍沿用原trace_valid取消；即使非依赖资料在过程中到期、回复能正常提交，也不会把不同快照的证据登记为有效。破坏性v1跨文件清理前会提前清缓存，部分失败后宁可失去瞬时诊断，不冒称删除已原子完成。旧跨文件非原子限制未解决。

只读 `feedback_view`不召回，不遍历别的场景，不读配置，不更新缓存/内存/文件/epoch/last_trace/last_notice/paused/inflight。它根据当前到期投影和现有turn有效性决定是否返回证据，缺缓存就降级。普通反馈继续只保存原标签、期望和既有版本/摘要；不把新证据混入turn、feedback、日志或JSON。

原UI的100ms事件循环只在反馈小窗存在时刷新该绑定Core/场景的元数据，内容未变则不重画；不是主动表达调度。选择标签不再附用户原话/助手摘要，防止删除后残留。窗口选择消失即清空，不替选另一人。证据框height=4带滚动条，256状态和32依赖长列表实际控件验证仍能填写并保存。提交后绘制失败保留submitted标记，重复回调不重提；回复显示失败从已提交轮次恢复，旧通知也不写缓存或重复对话。

基线202项通过；新增11项行为回归后213项通过。五个临时Tk脚本、原样例检查、中文启动器和干净进程导入通过。具体命令、失败边界与证据在 `第七阶段验证记录.md`，不是自然程度评分。

## 兼容和有意取舍

- 正式JSON内部v3/文件名v2、v2显式升级、旧trace v1保守来源、v1管理副本清理、raw与全删除祖先区分、话题revision_id、本地采用去重均保持。旧断言没有删改。
- 维护清全场景，哪怕被改资料与所选轮次无关，也可能只剩累计来源。普通新自述/话题变化也可能造成此结果。简单、可解释，但可用诊断时间较短；不能把没有缓存说成没有提供资料。
- 到期投影不物理删除缓存，下一次写入/关窗才释放；固定码和ID不含被删正文。若在只读状态下要求完全物理清空会违反只读保证，所以采用隐藏并延迟释放，明确区分。
- 本阶段未为候选评估/采用建立同等级证据。候选/公开取数范围不扩大，原活动写入保守清理，采用轮显示缺直接清单。普通反馈写入保持缓存；到期与状态变化仍优先。
- 不保存当时正文/quote，也没有资料内容版本档案。即使有ID清单，仍不能恢复当时每字内容、助手实际复述范围、模型关注点或理解过程；当前详情不是历史证据。
- 选择状态码基于现有诊断分支，`state_or_insufficient`合并状态或依据不足，不增加完整动态解释。查细节可用当前预览，但必须标成现在。
- 单进程、原单实例启动器与本地JSON限制仍在；没有多进程锁、断电整体事务、所有DPI或长时内存压力保证。UI按有界场景做快照/摘要检查，尚未作长时间性能测量。

## 给6 ASTRA ULTRA的复盘材料

**本轮解决的缺口：** 用户对某成功普通回复反馈时，若缓存仍可用，可以确认那次直接长期/近期/话题/助手选择，和仅经助手继承的依赖，而不拿新预览猜历史。mock实际请求逐项比对一致。足以分开“长期未选但近期提供”“纯累计依赖不能当正文”“选择后表达有问题”等诊断类别；仍不能仅凭ID证明模型理解，更不能替代授权原句的表达评估。

**新增删除/串场风险：** 缓存确实新增了临时元数据副本，因此禁止动态词/原话/quote，按Core/场景/轮次/人物绑定，资料写入保守清理，时钟投影隐藏，销毁释放。实际群/私聊与模式切换、维护/删除/到期、重复通知和显示失败已虚构验证。保守清理牺牲诊断留存，暂不为了方便放宽删除或做持久档案。

**是否支持调人格或语义能力：** 本轮没有真实用户模型样本。没有证据支持继续加人格禁令、更强语义服务、向量库或数据库；未动persona、主人温柔规则和第六阶段有限召回。原咖啡因洗发水误选、未覆盖别名、模糊指代等已知限制没有在本阶段宣称修复。

**下一步最值得体验：** 原8轮小说交流，随后拿铁/工作/颜色风格对照，再看两位朋友不同边界与主人参与。对一个具体问题立即查看那轮证据，记录标签和一句期望；只分析用户另行授权的少量样本。若没有对应资料，应先判断是否需要保存，而非把所有话长期留存。持续出现有证据的漏选或表达重复时再确定小范围任务；目前建议继续本地真实体验，没有足够依据自动规划第八阶段或大型架构。
